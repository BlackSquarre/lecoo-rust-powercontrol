# 登录启动、托盘与风扇控制

本文适用于 v0.0.2 及对应源码构建；v0.0.1 压缩包不包含这些功能。

## 登录启动

在“功能设定”勾选“当前用户登录后启动”。默认关闭，状态直接查询 Windows 计划任务；不会用本地布尔值代替实际状态。任务名称为 `LecooRustPowerControl-<当前用户 SID>`，同一用户反复启用只更新这一项。关闭后删除任务，再查询确认不存在。执行文件移动后旧任务会显示失效，重新启用可以修复路径。

任务使用当前用户的 `InteractiveToken`、`HighestAvailable` 与登录触发器，不保存密码、不作为 SYSTEM 运行；以 `--minimized` 启动到托盘。应用首次手动运行需要 Windows UAC 管理员确认，已注册的任务沿用该权限。此方案的权限要求见 [Microsoft Task Scheduler 安全上下文说明](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks)。硬件调用仍会检查提权状态。

测试会临时创建、重复更新、手动运行和删除任务，并恢复测试前已有的本应用任务。不会注销、重启电脑，因此真实的下一次登录触发仍需在正常登录时验证。

## 托盘

右键专属电源图标，可选择安静、均衡、性能、打开主窗口、最小化到托盘或退出。模式调用与主界面共用生产 WMI setter，必须读回实际模式才算成功；菜单勾选状态来自硬件轮询。切换失败会显示 Windows 错误提示。

双击图标打开窗口。默认关闭窗口即退出；“功能设定”可开启“关闭主窗口时缩到托盘”，该偏好保存在 `%LOCALAPPDATA%\LecooRustPowerControl\preferences.txt`。托盘菜单“退出”始终退出并清理图标。第二次运行会唤醒当前 Windows 会话的已有窗口，第二个进程随即退出。不同登录会话仍各有自己的窗口；手动风扇会话由全局锁限制为一个。

Windows 主线程消息定时器在窗口隐藏时继续处理托盘操作、硬件状态与风扇心跳。托盘注册失败时不隐藏主窗口；连接丢失会重开窗口。折叠区域中图标坐标可能不可查询，因此以 Windows 确认图标更新成功作为可用性依据。

## 风扇和温度

当前仅开放已验证的 Ryzen 7 8745H、指定 Lecoo WMI 实例、固件报告单风扇的写入路径。进入风扇页建立独立守护进程，并先请求自动控制；支持自动（固件编码 101）、最大（100）和手动目标 35–100%。拖动滑杆不会直接写硬件，点击“应用手动目标”才提交。手动偏好不会跨启动保存。

固件的 `GetFanControl` 返回实测 RPM，**没有实际占空比或自动/手动模式读回接口**。界面因此显示“本会话请求”及返回状态、实测 RPM；这不是占空比验证。35–100 来自本机官方程序约定，短时实机测试只能证明响应与转速变化，不能证明所有负载、环境温度下的长期安全。

手动控制需有效 CPU Package 温度及非零 RPM。温度来自独立 Rust 代码，通过已加载的 WinRing0 读取 AMD SMN，显示真实摄氏温度，不沿用官方界面的百分比缩放。应用不安装、启动或卸载内核驱动；没有现成驱动或温度采样不可用时显示不可用并拒绝手动控制。

保护行为：

- 参数校验在写入前完成；非法值拒绝。
- 手动开始前及运行中检查温度；达到 85°C、采样失败或主程序心跳超过 3 秒，提交自动恢复并读取 RPM。
- 正常退出、父进程关闭管道或退出，守护进程恢复自动并结束；GUI 发现守护进程异常结束时也会独立尝试自动恢复。
- 自动恢复失败最多尝试三次，然后请求最大风量备用，并显示失败。不能把通信失败后的恢复请求宣称为确定生效。
- 隐藏窗口继续控制；主线程冻结则不再发心跳，守护进程可以恢复自动。

进程同时被强制杀死、系统断电、固件失联或驱动在关机时提前卸载，不保证软件清理能执行；固件自动散热仍是最终保障。本应用不是独立硬件温控保护器。请避免同时使用官方应用与本应用手动调速：固件不提供外部写入者或目标模式读回，无法识别外部控制覆盖。

接口证据见[驱动和传感器调查](reference/wmi/native-sensor-research.md)，验证入口见[测试文档](testing.md)。
